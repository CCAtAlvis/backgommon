Generated by `go test ./bench -run TestImpactReport` plus Go microbenchmarks and
`gp-trade/cmd/fwbench` on the real NSE binary cache.

- Machine: darwin/arm64, GOMAXPROCS=8
- Synthetic grid: **S=2000** symbols; timed at **B=500** bars (extrapolate to 10k / 1M)
- Stretch goal: **1M bars × ~2000 symbols under 1s** (ideal &lt;100ms)
- Projections are **linear** from ns/bar unless noted
- Auto table from the test also lands in `RESULTS.generated.md`

## Decision summary

### Implement next (framework)

1. **E3 SoA OHLCV panel** (+ E11-friendly tight loops) — must-have for full-universe speed
2. **E2 MarketView API** backed by SoA (not `GetValue` loops)
3. **E1 Lazy next-bar** fills (per-order lookup)
4. **E4** `ForEachOpenPosition` / stop copying maps on hot path
5. **E5** equity fidelity dial + **E6** metrics-only export for sweeps

### Situational

- **E9 FeaturePanel** — yes as framework primitive; huge when features are expensive or shared across sweep trials; chunk/mmap at 1M bars
- **E7 GC off** — **no meaningful win** once maps are reused; do **not** make library default
- **E10 parallel per bar** — defer; overhead at S≈2k. Revisit as multi-bar batch parallel

### Reject / defer as primary fix

- **E8 sync.Pool for maps** — slower than reuse; obsolete if SoA lands
- **E12/E13/E14** — micro; revisit after E3
- Staying on `map[string]Candle` for full-universe loops — **reject** for moonshot path

## Precompute change-maps (answered)

- **Upside:** moves heavy cross-sectional math out of the bar loop; runtime becomes dense reads. Shared panels help sweeps when lookbacks are fixed.
- **Downside:** memory `B×S×F×8` (1M×2000×1 ≈ **16 GB** per float feature); param changes invalidate panels; does not remove B×S *reads* if you still scan every symbol every bar.
- **Verdict:** **keep as framework FeaturePanel**, chunked for large B; not a substitute for SoA.

## Disable GC? (answered)

- Measured **no speedup** on W1 with reused maps (E7a ≈ E7b).
- **Downside:** unbounded RSS — unsafe as default in an open-source library.
- **Verdict:** optional batch CLI only; **prefer eliminating allocs (E3/E4/E5)**.
